## 主题：风险指标体系融入三层漏斗 — 阶段 1a（财务层做厚，零采购）

依据 `prd/vibe+coding+...md` 四类风险指标体系（财务/商业/治理/行业）的融入规划
（`/opt/.claude/plans/sharded-booping-tome.md`），实施第一阶段中「零补字段、复用现有 canonical」的子集。

### 1. 新增 risk_v1 财务风险指标模块

`backend/metrics/risk_metrics.py`（formula_version=`risk_v1`）：

- **应计利润率 accruals_ratio** = (NetIncome − CFO) / 平均总资产，逐年计算 →
  截面 `accruals_3y_avg`（近 3Y 均值）。衡量利润含金量：值越大越差（NI 远超经营现金流 ⇒ 疑盈余操纵）；
  负值（CFO>NI）为利润质量好。
- **FCF 波动 fcf_cv_5y** = σ(FCF/Revenue) / |μ|，近 5Y 变异系数（FCF = CFO − CapEx）。衡量现金流稳定性。
- 仅用既有 canonical：`net_income / cfo / capex / total_assets / revenue`，**零补字段**。
- 接入 `compute.py::persist_all_metrics_for_company`（`_persist_risk` upsert 逐年 + 截面）。

全市场重算：598 公司，`accruals_3y_avg` 有值 492 只、`fcf_cv_5y` 有值 387 只（其余缺数据跳过）。
抽样核对：AMD 应计 −2.62% / FCF cv 0.429；美的 应计 −3.59% / cv 0.249（均健康，合理）。

### 2. 稳健层引入 hard / soft 三档分档

`backend/screening/funnel_v2.py::_eval_sturdiness` 重构为统一 `_grade()` 三档判定：

- **hard**（达硬阈）→ 记 hard 标签 + 出局；**soft**（介于软~硬阈）→ 记软警告（warning，不出局，仍可 MONITOR 通过）；缺失跳过。
- 5 条规则统一分档：net_debt/EBIT、利息保障、FCF<0 年数（原 3 条，新增 soft 区间）+ 应计利润率、FCF 波动（risk_v1 新增）。
- **软警告叠加升级**：soft 条数 ≥ `r_soft_stack_to_hard`（strict 2 / standard 3 / loose 4）→ 升级硬剔除
  （`STURDINESS_SOFT_STACK`），对齐原著「单一软信号不致命、多项叠加才剔除」。

`config.py` 新增 8 个软阈值 property（按 strict/standard/loose 分档）。
`reason_labels.py` 新增 9 个 reason code（2 hard + 6 soft + 1 叠加升级）。

### 3. 验证

抽样 120 只（有 risk_v1 指标）跑 `_eval_sturdiness`（ai off，standard）：通过 104 / 出局 16。
分档行为正确：
- BOEING（net_debt/EBIT 5.7 + FCF cv 2.2）→ 双 hard 出局；
- FCF cv 0.5~1 → soft 观察区，不出局通过；
- 应计负值（CFO>NI）不误伤。

### 3. 接入稳健层 + 阈值校准

**阈值核验与校准**：抽样核对 Apple/Microsoft/美的 CCC 为负（符合现实）、Apple Z''2.31（高回购致账面权益低）。
