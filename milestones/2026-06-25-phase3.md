# 2026-06-25 工作日志：阶段 3 商业深度风险融入漏斗（客户/供应商集中度 + segment HHI）

## 主题：原著「商业风险」量化落地——零采购从完整 10-K 抽取

阶段 1-2 已补完原著四类风险中的财务/治理/行业三类，**唯一缺口是商业风险**
（`diversified_customers` / `diversified_suppliers` 两条稳健原则此前是 AI-only 占位）。

**关键发现（推翻原"需采购"判断）**：管道 `filings_text.py` 其实下载了完整 10-K HTML（含内联 XBRL），
只为给 AI 瘦身丢弃正文、仅留 8KB Item 1A 切片。商业集中度数据就在被丢弃的正文里——**美股可零采购实现**。

## 1. 抽取管道 `backend/pipeline/commercial/`

### `sec_commercial.py`（美股，iXBRL 优先 + 文本兜底）
- **客户集中度** `top_customer_revenue_pct`：抽 iXBRL `us-gaap:ConcentrationRiskPercentage1`，
  经 context 维度**四重精确筛选**才认：① benchmark=营收口径（兼容 `RevenueFromContractWithCustomer` /
  `SalesRevenueNet`，排除应收）② type=`CustomerConcentrationRisk`（排除地理/产品/渠道）
  ③ 存在具体大客户成员 `MajorCustomersAxis` ④ 仅**文档主报告期**（max duration end，排除比较期/封面瞬时日期）。
  再**排除合并客户群 / 销售渠道成员**（`fivelargestcustomers`/`combined`/`channelpartners`/`directcustomers` 等会高估 top1）。
- **segment 收入 HHI** `segment_revenue_hhi`：抽 `RevenueFromContractWithCustomer` 且 context 仅
  `ConsolidationItems=OperatingSegments × StatementBusinessSegments` 两轴的分部营收，算 Σ(share²)；
  排除公司/抵消项成员；单一分部不计（避免 HHI=1 噪声）。
- **供应商集中度**：美股极少披露采购占比数字 → 仅定性正则（sole/limited/single source）做 soft 旗标，写 `governance_signal`。
- 落库：客户%/HHI 入 `metric_periodic`（formula_version=`commercial_v1`）；供应商入 `governance_signal`（复用阶段2 通用表）。

### `tushare_segment.py`（A股 segment HHI，零采购）
- 复用 Tushare `fina_mainbz`(type=P 主营构成)，去重「其他/合计/小计/抵销」兜底行 + 按金额去重层级，算 HHI。
- 写同一 `metric_periodic`（commercial_v1，同 metric 名）→ **漏斗按 metric 名跨市场统一消费，零改动支持 A股**。

## 2. 漏斗集成 `funnel_v2._eval_sturdiness`

- 新增读 `top_customer_revenue_pct` / `segment_revenue_hhi`（`_latest_section commercial_v1`）+ 供应商旗标（`_has_supplier_concentration`）。
- 各加 `_grade` 三档（hard/soft/pass），供应商为 soft 计入软警告叠加。
- **硬事实优先**：有 10-K 数据时 `diversified_customers` / `diversified_suppliers` 原则按规则判定（覆盖 AI 占位），无数据回落 AI。
- config 加 4 阈值（`r_customer_concentration_soft/hard`、`r_segment_hhi_soft/hard`），reason_labels 加 5 个中文标签。

## 3. 关键坑（实测踩出，已修）

| 坑 | 现象 | 修复 |
|----|------|------|
| benchmark 误纳 | 只筛营收口径 → 地理/产品/渠道集中度全被当客户（Cloudflare/Zoom 误报 100%） | 加 type=CustomerConcentrationRisk + 必须有 MajorCustomersAxis 成员 |
| 旧营收概念 | Fabrinet 用 `SalesRevenueNet` → 漏掉真实 NVIDIA 27.6% | benchmark 成员改白名单 frozenset |
| 比较期混入 | 取跨年 max → AMD 拿到 FY2023 旧值（FY2025 实为无客户>10%） | 锚定主报告期（仅 duration context 的 max end） |
| 合并客户群 | General Mills「前五大客户」66% → 误杀正常消费股（真实 Walmart 仅 31%） | 排除 `customers`复数/`combined`/`largest`/数字词成员 |
| 销售渠道 | Zscaler `channelpartners` 91% 非单一客户依赖 | 排除 `channel`/`distributor`/`reseller`/`partner`/`directcustomer` |

## 4. 验证

- **单测** `tests/test_commercial_extract.py`：18 项全过（含上表 5 类误报排除 + 取单一客户而非合并 + 文本兜底）。
- **全市场回填**：美股 813 份 10-K 全成功 0 失败；客户 45 家、segment HHI（美 246 + A 48）、供应商 320 条。
- **客户集中度 top 核验**：BWX 0.91(美政府)、Credo 0.67、DexCom 0.55、Crown Castle 0.40(T-Mobile)、Fabrinet 0.35(NVIDIA)、
  General Mills 0.31(Walmart, soft 不误杀)——全为真实单一客户依赖，无残留误报。
- **净效应 tally**（322 家有数据）：客户 hard 仅 4、segment hard 18、因商业 hard 直接出局 22（~7%），
  soft（供应商114/segment67）走叠加机制不批量出局——符合「soft 为主、hard 设深」基调，无误杀。
- **端到端**：BWX hard 出局(diversified_customers=fail)、GIS soft watch 通过、万科 segment 0.735+叠加出局、美的 0.599 临界通过。

## 5. A股客户/供应商集中度——可行性结论（用户要求评估）

- ✅ **segment HHI 已免费实现**（Tushare `fina_mainbz`，token 有权限）。
- ❌ **客户/供应商集中度无免费结构化数据**：Tushare 全部接口均无此字段；数据仅在巨潮年报 MD&A 文本（本项目 A股 annual 文本为空）。
- **采购建议**：① 零采购但重 = 巨潮年报解析；② 采购优先 **CSMAR 国泰安「客户与供应商」专题库**（性价比），
  或 **Wind / 同花顺 iFinD / 东方财富 Choice**（有「前五大客户占比」结构化字段）。
