## 四、核心问题：Cognizant「筛选页入选、详情页未进后两层」→ 漏斗改全自动

**现象**：用户新建 run 27，Cognizant 在筛选页显示入选，详情页却显示稳健性/风险性「未进入此层」。

**诊断**（非 bug，是分层 gate 的中间态）：run 27 停在 `current_layer=roce, layer_status=awaiting_review`，
ROCE 层跑完等人工覆核，后两层根本没执行。Cognizant 仅 `layer_results.roce` 有数据，详情页
`CompanyDetailV2.vue:88` 因 `sturdiness/risk` 为空渲染「未进入此层」。根因是 `status` 在 ROCE 层
就被打成乐观的 `HighConviction`，语义超前于漏斗实际进度。

**用户决策**：要全自动——过 ROCE 自动进稳健性、过稳健性自动进风险性、通过风险性的才是最终列表，
**不要逐层人工 gate**。引擎 `funnel_v2.run_from` 早已支持 `auto_advance=True` 连跑，只是默认值是手动。

### 改动 1：默认全自动（commit `0b262f2`）
- `ScreenRunCreateRequest.auto_advance` 默认 `False → True`；
- 前端 `UniverseConfig` 创建筛选传 `auto_advance: true`。
- run 27 处理：切 `auto_advance=1` 并从稳健层连跑到 done。zheyang 已绑 chatgpt key，
  风险层**真实 AI 判定**（返回 PASS、无标签，非降级）。结果：Cognizant 通过 ROCE/稳健/风险
  三层，最终入选 `HighConviction`，`status=completed`。

### 改动 2：清理 FunnelResults 人工 gate UI（commit `cbe4d72`）
全自动后 `awaiting_review` 永不出现，移除不再触发的交互：gate 块（剔除/推进按钮）、被过滤行
放行按钮与「人工」标记、`doAdvance/doPass/doReject/canManage/isAwaiting/advanceLabel/advancing`
及相关 import 与样式；简化 `runStateText/runStateClass`。保留纯展示：进度 → 三层漏斗 → 最终入选。

### 改动 3：移除人工 gate 的 HTTP 层（commit `d5efaac`）
- 删 `POST /v2/screen-run/{id}/advance`、`/manual` 两端点及 import；
- 删 schema `AdvanceResponse`、`ManualActionRequest`；
- 删前端 api 导出 `advanceLayer`、`manualAction`（已无组件引用）。
- 运行时实测两端点均 **404**；后端整体 import 通过、screening 路由 17 个无 advance/manual。
- **保留**：引擎层 `funnel_v2.finalize_run` / `run_from` 非 auto 分支（引擎能力，无 HTTP 入口，
  仅更新过时注释）；`manual_action` **数据字段**（ScreenResult 列 + 详情展示是否人工干预过）。

### 6.2 用户实测："第二、三层漏斗没过滤掉任何股票"
核查 run 28/29（ai_mode=full）：所有过滤都在 ROCE 层，稳健层 / 风险层 rejected 均为 0。
根因两层叠加：

1. **证据检索点时 bug（commit `6524b03`）**：`orchestrator._load_recent_documents` 先按
   `published_at desc` 取最近 limit 份、再在 Python 剔除 as_of 之后的文档。库内 Polygon News
   多为 2026-05 灌入，as_of=2025-12-31 时最近 N 份几乎全是未来文档 → 点时过滤后**喂给 AI 的
   证据为 0** → AI 裸看财务一律 PASS。修复：点时过滤 `published_at < asof+1天` 移入 SQL WHERE
   （LIMIT 之前）。实测 AMD 证据份数 0→10；重跑后 AI 改基于真实 SEC/News，出现 REVIEW + 风险标签。
2. **过滤标准过松（commit `52fee38`）**：此前仅 `ai_action=REJECT` 才剔除存活集（REJECT 门槛
   极高：≥0.8 置信 + 法定披露），REVIEW 仍入选。按用户决策（排除法）改为
   **REVIEW/REJECT 出局、PASS/MONITOR 通过**（MONITOR="有轻微迹象但不阻止"，按设计语义放行）；
   `ai_action=None`（未跑 AI/降级）不误杀。新增兜底 code `STURDINESS_AI_REVIEW`/`RISK_AI_REVIEW` + 中文 label。

验证：run28 universe 出 REVIEW 时稳健层过滤 1 家；MONITOR 正确放行。后两层现能有效过滤。

> overall_action 四档：PASS（无风险）< MONITOR（轻微但不阻止）< REVIEW（中/高风险需复核）< REJECT（确凿）。
